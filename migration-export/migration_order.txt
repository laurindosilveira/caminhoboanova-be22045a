ORDEM DE MIGRAÇÃO PARA O NOVO SUPABASE

1. EXECUTAR schema.sql
   - Isso criará todas as tabelas, funções, triggers e policies no schema public.
   - Certifique-se de que as extensões necessárias (uuid-ossp, pg_cron, etc.) estejam habilitadas no novo projeto.

2. DESATIVAR TRIGGERS PERIGOSOS
   - Antes de importar os dados, desative triggers que enviam emails ou push automaticamente para evitar spam durante a migração.
   - Comando: SET session_replication_role = 'replica'; (já incluído nos scripts de dados).

3. EXECUTAR auth_data.sql
   - Importa os usuários e identidades.
   - IMPORTANTE: Como as senhas estão hasheadas, os usuários poderão logar normalmente se o algoritmo de hash for compatível (Supabase usa bcrypt por padrão).

4. EXECUTAR public_data.sql
   - Importa todos os dados do aplicativo.
   - A ordem de inserção respeita as chaves estrangeiras.

5. EXECUTAR storage_metadata.sql
   - Registra os buckets e a existência dos arquivos no banco de dados.

6. IMPORTAR storage_files.zip
   - Faça o upload manual ou use um script para enviar os arquivos físicos para os respectivos buckets no novo Storage.

7. DEPLOY DAS EDGE FUNCTIONS
   - Use os arquivos em edge_functions.zip para recriar as funções no novo projeto.
   - Comando: supabase functions deploy [NOME_DA_FUNCAO]

8. CONFIGURAR SECRETS
   - Configure todas as chaves de API (Stripe, Vapid, WhatsApp, etc.) no novo dashboard.

9. TESTAR AMBIENTE
   - Verifique logins, profiles e carregamento de arquivos.

10. REATIVAR TRIGGERS E CRON JOBS
    - Garanta que tudo está operando no novo ambiente.
